# usage-guard

Заранее останавливает Claude Code при достижении порога лимита подписки и планирует продолжение после сброса – вместо резкой остановки посреди задачи. Например: «остановись на 80% пятичасового лимита и продолжи после сброса».

## Как это работает

1. **Статус-строка** показывает `29% до 13:10 · 94% до 16:00 12.10` (пятичасовое окно, недельное окно) и сохраняет значения в файл. Claude Code передаёт процент использования только скрипту статус-строки.
2. **Хук** после каждого инструмента и перед каждым запросом читает файл. Когда процент достиг порога, он добавляет в контекст указание: закончить шаг, записать заметки, запланировать одноразовое продолжение на время сброса плюс две минуты и остановиться.
3. Порог не задан – хук ничего не делает.

## Требования

- подписка Claude Pro или Max (у остальных данных о лимитах нет);
- интерактивная сессия: в `claude -p` статус-строки нет, данных не будет;
- `bash` и `jq` (если `jq` нет: `brew install jq`; без него защита не работает, а плагин предупредит об этом при старте сессии); остальное – стандартные утилиты (`find`, `ln`, `mv`, `mkdir`, `readlink`);
- macOS; на Linux скрипты не проверялись.

## Установка

```
/plugin marketplace add <github-user>/usage-guard
/plugin install usage-guard@usage-guard
```

Затем, в той же сессии:

```
/usage-guard:config подключи статус-строку
/usage-guard:config остановись при 80% пятичасового лимита
```

Скил создаст стабильный путь `~/.claude/usage-statusline.sh`, добавит `statusLine` в `~/.claude/settings.json` (после подтверждения) и запишет порог. Если у тебя уже своя статус-строка, скил предложит встроить вызов, не заменяя её.

Вручную: порог – файл `~/.claude/usage-guard.json`:

```json
{ "five_hour": 80, "seven_day": 95 }
```

Ключа нет – окно не проверяется. Файла нет – хук выключен. Этот файл – общий порог для всех сессий.

Порог одной сессии лежит в `~/.claude/state/ug-limit-<id сессии>.json` (тот же формат; id – `$CLAUDE_CODE_SESSION_ID`) и перекрывает общий. Скил по умолчанию пишет именно его: «остановись при 60%» в одном диалоге не останавливает остальные.

## Что произойдёт на пороге

Claude получит одно сообщение `USAGE GUARD:` на все сработавшие окна, допишет текущий шаг, сохранит заметки и создаст одноразовое задание `CronCreate` на время сброса (если до сброса больше 12 часов, сначала спросит тебя: сессия вряд ли доживёт). Сообщение повторяется каждые 5 п.п. роста и на каждый новый запрос, пока лимит выше порога: это страховка на случай, если при сжатии контекста оно потеряется, и напоминание после возобновления по расписанию. Субагенты получают короткую версию без расписания.

После ручного сброса лимита (процент упал в том же окне) хук забывает прежние срабатывания и сработает заново при следующем росте.

## Настройка через переменные окружения

| Переменная | По умолчанию | Назначение |
| :- | :- | :- |
| `CLAUDE_CONFIG_DIR` | `~/.claude` | базовый каталог всех файлов ниже (если у тебя он нестандартный) |
| `USAGE_GUARD_CONFIG` | `~/.claude/usage-guard.json` | файл с порогами |
| `USAGE_GUARD_DATA` | `~/.claude/rate_limits.json` | последние лимиты, пишет статус-строка |
| `USAGE_GUARD_STATE_DIR` | `~/.claude/state` | служебные файлы дедупликации |
| `USAGE_GUARD_SHARED_DIR` | не задана | каталог, общий для нескольких компьютеров (Dropbox и т.п.) |

Переменные удобно задавать в `env` файла `settings.json`.

### Несколько компьютеров

Лимит общий на аккаунт, а каждый компьютер видит только свои ответы. Чтобы они узнавали о расходе друг друга, задай `USAGE_GUARD_SHARED_DIR` на общую синхронизируемую папку. Каждый компьютер пишет туда свой файл `rate_limits.host-<пользователь>-<имя машины>.json` (один писатель на файл, конфликтных копий не будет; имена двух машин должны различаться), хук читает все и берёт самое свежее наблюдение. Порог тоже можно сделать общим: сделай `~/.claude/usage-guard.json` симлинком на файл в той же папке. Общий каталог – доверенная зона: любой, кто может в него писать, может подделать данные о лимитах, а имя компьютера попадает в имя файла.

## Ограничения

- Расписание продолжения живёт, пока открыта сессия и компьютер не спит. Закрытие Claude Code или сон отменяют его.
- Данные приходят после ответа модели: хук видит процент на один ответ позади. Порог 95% лучше держать с запасом.
- Если шаг долгий и без вызовов инструментов, хук не вмешается до его конца.
- Хук лишь напоминает: выполнит ли модель указание, от него не зависит. Для недельного окна сброс может быть через несколько дней, и расписание столько не проживёт.
- Статус-строку плагин подключить сам не может (в `settings` плагина допустимы только `agent` и `subagentStatusLine`), поэтому нужен однократный шаг `/usage-guard:config`.

## Удаление

`/usage-guard:config отключи и удали usage-guard` покажет план и (после подтверждения) уберёт `statusLine`, служебные файлы и пороги. Затем `/plugin uninstall usage-guard@usage-guard`. Если убрать плагин без этого, `statusLine` в `settings.json` останется и покажет ошибку «No such file» – удали его вручную.

## Выпуск версий

В `plugin.json` задана `version`: пользователи получают обновление, только когда эта строка меняется. Меняй её при каждом изменении скриптов или скила.

## Состав

```
.claude-plugin/plugin.json
hooks/hooks.json            PostToolUse, UserPromptSubmit – проверка; SessionStart – симлинк статус-строки
scripts/usage-guard.sh      хук
scripts/statusline.sh       статус-строка и сохранение лимитов
scripts/link-statusline.sh  стабильный путь ~/.claude/usage-statusline.sh
skills/config/SKILL.md      настройка порога и подключение
tests/run.sh                тесты (bash tests/run.sh)
```

## Безопасность

Токены и секреты плагину не нужны. Скрипты читают и пишут только файлы в `~/.claude` (или `CLAUDE_CONFIG_DIR`), по путям из переменных `USAGE_GUARD_*` и в каталоге `USAGE_GUARD_SHARED_DIR`. Файлы создаются с правами только для владельца.
