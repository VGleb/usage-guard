# usage-guard: настройка

Хук проверяет лимиты подписки (окна 5 часов и 7 дней) после каждого инструмента и перед каждым запросом. Когда порог достигнут, он добавляет в контекст сообщение `USAGE GUARD:` – по нему нужно остановиться и запланировать продолжение. Пока порог не задан, хук ничего не делает.

Данные о лимитах приходят только в интерактивной сессии (не в `claude -p`), только для подписок Pro и Max и только после первого ответа модели. Их собирает статус-строка, поэтому ей нужно быть подключённой.

Пути (`<cfg>` – это `$CLAUDE_CONFIG_DIR`, по умолчанию `~/.claude`; переменные окружения описаны в `${CLAUDE_PLUGIN_ROOT}/README.md`):

- порог текущей сессии: `<cfg>/state/ug-limit-<id сессии>.json` (каталог – `USAGE_GUARD_STATE_DIR`);
- общий порог для всех сессий: `<cfg>/usage-guard.json` (`USAGE_GUARD_CONFIG`);
- последние лимиты: `<cfg>/rate_limits.json` (`USAGE_GUARD_DATA`).

Любая запись в файл настроек пользователя (`settings.json`) – только после того, как ты показал, что именно добавишь, и получил «да».

## Задать порог

На запросы вида «остановись при 80% пятичасового лимита», «95% недельного».

**По умолчанию порог действует только в текущей сессии**: остальные открытые диалоги его не видят и не останавливаются. Общий порог (для всех сессий) ставь только если пользователь прямо сказал «для всех сессий» / «везде» / «по умолчанию».

1. Определи окно: `five_hour` (пятичасовое) или `seven_day` (недельное) и порог – число больше 0 и не больше 100.
2. Обнови только нужный ключ одной командой (переменные между вызовами Bash не сохраняются – шаблон самодостаточный). `W` – окно, `V` – порог, `SCOPE` – `session` (по умолчанию) или `all` (только по прямой просьбе):
   ```bash
   W=five_hour V=80 SCOPE=session; umask 077
   cfg="${CLAUDE_CONFIG_DIR:-$HOME/.claude}"; d="${USAGE_GUARD_STATE_DIR:-$cfg/state}"
   if [ "$SCOPE" = all ]; then f="${USAGE_GUARD_CONFIG:-$cfg/usage-guard.json}"
   else [ -n "$CLAUDE_CODE_SESSION_ID" ] || { echo "нет id сессии"; exit 1; }; f="$d/ug-limit-${CLAUDE_CODE_SESSION_ID:0:100}.json"; fi
   mkdir -p "$(dirname "$f")"; [ -s "$f" ] || echo '{}' > "$f"
   jq --arg w "$W" --argjson v "$V" '.[$w]=$v' "$f" > "$f.tmp" && cat "$f.tmp" > "$f"; rm -f "$f.tmp"; echo "$f"; cat "$f"
   ```
   `cat >` вместо `mv` не заменяет симлинк обычным файлом (общий файл может лежать в общей папке). Порог сессии перекрывает общий; субагенты этой сессии используют тот же порог; после `/clear` порог переходит в новую сессию. Если id сессии недоступен, не пиши общий файл молча – скажи пользователю и предложи общий порог.
3. Покажи итоговое содержимое файла и скажи, на какую область он действует (эта сессия / все).
4. Проверь, что статус-строка подключена (раздел ниже). Без неё порог не сработает – скажи об этом.

## Выключить порог

Тот же шаблон с `V=null`: в файле сессии `null` выключает окно и тогда, когда задан общий порог (просто удалить ключ из файла сессии недостаточно – сработает общий). Общий порог выключай только по прямой просьбе (`SCOPE=all`).

Всё сразу в этой сессии – запиши `null` в оба окна. Общий порог целиком – удали файл `<cfg>/usage-guard.json`.

## Подключить статус-строку

Статус-строка нужна, чтобы получать данные о лимитах. Плагин держит копию актуальной версии скрипта по стабильному пути `<cfg>/usage-statusline.sh` (копию, а не симлинк: каталог версии плагина удаляется после обновления).

1. Создай копию (то же самое делает хук `SessionStart` в начале каждой сессии):
   ```bash
   cfg="${CLAUDE_CONFIG_DIR:-$HOME/.claude}"; mkdir -p "$cfg" && cp "${CLAUDE_PLUGIN_ROOT}/scripts/statusline.sh" "$cfg/usage-statusline.sh.tmp" && chmod 755 "$cfg/usage-statusline.sh.tmp" && mv -f "$cfg/usage-statusline.sh.tmp" "$cfg/usage-statusline.sh" && ls -l "$cfg/usage-statusline.sh"
   ```
2. Найди `statusLine` в трёх местах, по убыванию приоритета: `.claude/settings.local.json` и `.claude/settings.json` текущего проекта, затем `<cfg>/settings.json` (если это симлинк – правь по цели). Проектные перекрывают пользовательский: если `statusLine` задан там, подключение в пользовательском файле не сработает – скажи об этом.
   - `statusLine` нигде нет – покажи, что добавишь, дождись «да» и добавь в `<cfg>/settings.json`:
     ```bash
     f="${CLAUDE_CONFIG_DIR:-$HOME/.claude}/settings.json"; [ -s "$f" ] || echo '{}' > "$f"
     jq '.statusLine={"type":"command","command":"~/.claude/usage-statusline.sh"}' "$f" > "$f.tmp" && cat "$f.tmp" > "$f"; rm -f "$f.tmp"
     ```
     (если `CLAUDE_CONFIG_DIR` задан, в `command` подставь полный путь `<cfg>/usage-statusline.sh`).
   - `command` уже содержит `usage-statusline.sh` – ничего не делай.
   - есть другая статус-строка – **не заменяй**. Предложи встроить вызов. В bash-скрипте пользователя в самом начале:
     ```bash
     in=$(cat); printf '%s' "$in" | ~/.claude/usage-statusline.sh >/dev/null
     ```
     дальше его скрипт работает с `$in` вместо stdin. Если `command` – не bash-скрипт (python, node, inline-команда), предложи обёртку: `in=$(cat); printf '%s' "$in" | ~/.claude/usage-statusline.sh >/dev/null; printf '%s' "$in" | <прежняя команда>`. Правь чужой скрипт только после «да».
3. Статус-строка появится в новой сессии; если не появилась в текущей – перезапусти.

## Показать лимиты

Прочитай `<cfg>/rate_limits.json` (`USAGE_GUARD_DATA`) и выведи по каждому окну: процент, время сброса в локальной зоне (`resets_at` – unix-секунды), заданный порог. Нет файла – лимиты ещё не приходили: нужна интерактивная сессия с подключённой статус-строкой.

## Отключить и удалить

Если пользователь хочет убрать usage-guard целиком: покажи план и после «да» удали `statusLine` из `<cfg>/settings.json` (если он указывает на `usage-statusline.sh`; иначе статус-строка превратится в ошибку), затем файлы `<cfg>/usage-statusline.sh`, `<cfg>/usage-guard.json`, `<cfg>/rate_limits.json`, `<cfg>/state/ug-*`, `<cfg>/state/statusline-*`, а при заданном `USAGE_GUARD_SHARED_DIR` – свой `rate_limits.host-*.json`. После этого `/plugin uninstall usage-guard@usage-guard`.

## Когда пришло сообщение `USAGE GUARD:`

Выполни его указание: заверши текущий шаг, запиши заметки о прогрессе в файл и сделай с расписанием ровно то, что сказано в сообщении (готовое cron-выражение уже посчитано хуком), сообщи пользователю и остановись. Чужие повторяющиеся задания не удаляй. Расписание живёт, пока открыта сессия и компьютер не спит, – скажи об этом пользователю. Сообщение повторяется каждые 5 п.п. роста, на каждый новый запрос и после сжатия контекста, пока лимит выше порога, – это страховка, а не ошибка.
